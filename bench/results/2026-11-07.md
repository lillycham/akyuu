# Archive preparation and concurrent writes, 2026-11-07

Archive preparation no longer holds the mutation lock. GC prepares its
archive first, then checks the expected checkpoint under the lock. A write
during preparation makes the collection stale before any eviction.

Accepted inventories only grow. Archive paths contain immutable bytes.
Concurrent preparers can save the same payloads and manifests. GC saves
those bytes before it removes an active copy, so snapshot readers retain
archive fallback. Archive preparation does not acknowledge remote publication.

## Barrier experiment

The experiment used native aarch64-darwin, GHC 9.10.3 and fresh synthetic
fixtures. The driver used `-O2`, two RTS capabilities and a 2 GiB heap cap.
The library used its Cabal development build. Product code was `23483af`
before the rebase; `c983777` retains the same archive change on current main.

The fixture used the compressible body profile from the earlier report.
The command paused the first archive payload write. An ordinary topic read
and replacement had to finish before archive preparation could continue.
Timers exclude process startup. The archive timer includes the deliberate
pause for the writer. Each size has one observation.

| Base entries | Payload objects | Writer, ms | Archive including writer pause, ms |
| --- | ---: | ---: | ---: |
| 100 | 105 | 65.481 | 116.265 |
| 5,000 | 5,189 | 3,397.843 | 6,180.595 |

Both writes succeeded while archive progress was paused. Acknowledgement of
the captured archive preserved each later write as pending. The fixtures
used no live store or remote. The harness removed them after the experiment.

These observations verify the lock boundary. They do not establish a latency
improvement or performance acceptance. Full inventory validation still occurs
on snapshot loads and inside writer transactions. Two-writer contention,
unchanged sync cost and the earlier Linux archive timeout need further work.
The experiment did not repeat Linux or SSH checks.

Five new regressions cover a writer during archive preparation, concurrent
preparers, GC during archive preparation, a stale GC plan and foreign snapshots.
The existing archive tests retain their process-death and corruption checks.
Archive crash workers now start fresh executable processes. One fork-only
worker exited with a segmentation fault instead of its requested fault exit
during the first combined test run. Fresh workers avoid the parent runtime.

After the rebase onto main `ae13433`, all 1,549 Haskell tests passed in the
development shell and native aarch64-darwin Nix sandbox. Every native flake
check passed. Packaged CLI/MCP/HTTP, browser-script, sync/join/GC/migration,
manual, format and legacy compatibility checks passed. Provenance tests had
their required `zstd` tool. The rebase preserves the topic tool set and the
provenance code from main.

## Reproduction

Build the fixture driver as described in [the experiment guide](../README.md).
Use a new root for each size:

```sh
/tmp/akyuu-sync-bench seed /tmp/new-fixture 5000 +RTS -N2 -M2G -RTS
/tmp/akyuu-sync-bench archive-writer /tmp/new-fixture +RTS -N2 -M2G -RTS
```

Both commands have a 120-second deadline. `archive-writer` refuses a fixture
that already has an archive. Its output records the two durations and the
pending-write check.
